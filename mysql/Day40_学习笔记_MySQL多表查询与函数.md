## 一、DQL（数据查询语言）

### 1.1 基本查询

| 场景 | 语法 | 说明 |
|---|---|---|
| 查询多个字段 | `select 字段1,字段2... from 表名` | — |
| 查询全部字段（方式一） | `select 字段1,字段2,字段3,字段4 from 表名` | **项目中推荐使用** |
| 查询全部字段（方式二） | `select * from 表名` | 仅学习过程中使用 |
| 设置别名 | `select 字段1 as 别名1, 字段2 as 别名2 from 表名` | `as` 可以省略 |
| 去重 | `select distinct 字段 from 表名` | — |

### 1.2 条件查询（where）

**比较运算符**

| 运算符 | 含义 | 备注 |
|---|---|---|
| `>` | 大于 | |
| `>=` | 大于等于 | |
| `<` | 小于 | |
| `<=` | 小于等于 | |
| `=` | 等于 | ⚠️ 跟 Java 中的 `==` 不一样 |
| `!=` | 不等于 | |
| `between 起始值 and 结束值` | 范围查询 | 包含起始值和结束值（闭区间） |
| `in(值1,值2,值3...)` | 多选一 | 可用 `or` 替代 |
| `like` | 模糊匹配 | `_` 表示任意单个字符，`%` 表示任意多个字符 |
| `is null` | 判断为 null | |
| `is not null` | 判断不为 null | |

**逻辑运算符**

| 运算符 | 含义 |
|---|---|
| `and` | 与 |
| `or` | 或 |
| `not` | 非 |

### 1.3 分组查询

**聚合函数**（⚠️ 所有聚合函数都会自动过滤掉 `null` 值）

| 函数 | 作用 |
|---|---|
| `sum` | 求和 |
| `max` | 最大值 |
| `min` | 最小值 |
| `count` | 统计计数（推荐写 `count(*)` 或 `count(1)`） |
| `avg` | 平均值 |

```sql
group by 分组字段1, 分组字段2... having 分组之后的过滤条件
```

- **where 与 having 的区别**：`where` 是分组前过滤，`having` 是分组后过滤
- **执行顺序**：`where` ---> 聚合函数 ---> `having`
  - `where` 中不能使用聚合函数
  - `having` 中可以使用聚合函数
- 分组之后，`select` 后面**只能书写分组字段和聚合函数**，其它字段不要写

### 1.4 排序查询

```sql
order by 字段1 排序方式1, 字段2 排序方式2
```

- 当字段1相同时，才按字段2进行排序
- `asc` 升序（默认）
- `desc` 降序

### 1.5 分页查询

```sql
limit 起始索引, 查询记录数
```

- 分页查询是"方言"，每个关系型数据库语法不一样
- 起始索引为 0 时可省略
- 前台传过来的是**页码**和**每页记录数**，后台需要计算起始索引：

  ```
  起始索引 = (当前页码 - 1) × 每页记录数
  ```

### 1.6 书写顺序 vs 执行顺序 ⭐

| 书写顺序 | 执行顺序 |
|---|---|
| select | from |
| from | where |
| where | group by |
| group by | having |
| having | select |
| order by | order by |
| limit | limit |

## 二、MySQL 常用函数

### 2.1 字符串相关

| 功能 | 示例 | 说明 |
|---|---|---|
| 去除首尾空格 | `select trim('  abc bdc  ');` | 中间空格不去除 |
| 截取字符串（三参数） | `select substring('abcd', 1, 2);` | 参数：原字符串、起始位置(从1开始)、截取长度 |
| 截取字符串（二参数） | `select substring('abcd', 2);` | 从起始索引截取到末尾 |
| 字符串拼接 | `select CONCAT('aaa', 'bbb');` | — |
| 获取字节长度 | `select LENGTH('a');` / `select LENGTH('你');` | MySQL8 默认 utf8，英文占1字节，中文占3字节 |
| 获取字符个数 | `select CHAR_LENGTH('aaa你');` | 跟字符集无关 |
| 转大写 | `select UPPER('abc');` | — |
| 转小写 | `select LOWER('ABC');` | — |
| 字符串替换 | `select REPLACE('abcabc', 'a', 'A');` | 参数：原字符串、旧值、新值 |
| 左侧截取 | `left(字符串, length)` | 从左侧获取指定长度内容 |

### 2.2 日期相关

| 功能 | 示例 |
|---|---|
| 当前年月日时分秒 | `select now();` |
| 当前年月日 | `select curdate();` / `select current_date()` |
| 当前时分秒 | `select curtime();` / `select current_time()` |
| 获取年份 | `select year(now());` |
| 获取月份 | `select month(now());` |
| 获取日 | `select day(now());` |
| 两日期相差天数 | `select datediff(日期1, 日期2)`（日期1 - 日期2） |

### 2.3 数值相关

| 功能 | 示例 | 结果 |
|---|---|---|
| 向上取整 | `select ceil(1.1);` | 2 |
| | `select ceil(1.7);` | 2 |
| 向下取整 | `select floor(1.1);` | 1 |
| | `select floor(1.7);` | 1 |
| 生成随机数 | `select rand();` | 0~1之间随机数 |
| 四舍五入 | `select round(3.241, 2);` | 3.24 |

### 2.4 流程控制相关

| 函数 | 语法 | 类比 |
|---|---|---|
| `if` | `if(条件表达式, true的返回值, false的返回值)` | 类似 Java 三元表达式 |
| `ifnull` | `ifnull(value1, value2)` | value1 不为 null 返回 value1，否则返回 value2 |
| `case ... when`（变量匹配） | `case 变量 when 值1 then 结果1 when 值2 then 结果2 ... else 结果n end` | 类似 Java 的 `switch` |
| `case ... when`（条件匹配） | `case when 条件1 then 结果1 when 条件2 then 结果2 ... else 结果n end` | 类似 Java 的 `if-else if` |

## 三、表关系设计

### 3.1 三种关系的设计方式

| 关系类型 | 设计方式 |
|---|---|
| **一对多** | 在"多"的一方添加逻辑外键，指向"一"方的主键 |
| **一对一** | 在任意一方添加**唯一**逻辑外键，指向另一方的主键 |
| **多对多** | 定义中间表，中间表至少包含 2 个逻辑外键，分别指向另外两张表的主键 |

### 3.2 逻辑外键 vs 物理外键

| 类型 | 特点 |
|---|---|
| 逻辑外键 | 只有外键字段，**没有**外键约束 |
| 物理外键 | 既有外键字段，**也有**外键约束 |

添加物理外键约束的语法：

```sql
constraint 约束名称 foreign key (外键字段) references 一方表名(id)
-- 约束名称示例: fk_dept_id
```

### 3.3 ⚠️ 实际项目中的选择

**实际项目中不会设计物理外键**，只设计逻辑外键（不建立外键约束）。

- **为什么？** 建立物理外键后效率低下，且不支持集群环境。
- **如何保证数据一致性？** 通过代码中的业务校验，校验通过后才进行数据库操作。

### 3.4 案例：分类表、菜品表、套餐表

- 分类表 —— 菜品表：**一对多**
- 分类表 —— 套餐表：**一对多**
- 套餐表 —— 菜品表：**多对多**

## 四、多表查询

### 4.1 连接查询

| 连接类型 | 关键字 | 说明 |
|---|---|---|
| 交叉连接 | `cross join` | 笛卡尔积，两表所有组合情况 |
| 内连接 | `inner join` | 只返回匹配连接条件的记录 |
| 左外连接 | `left join` | 匹配的记录 + 左表中不匹配的记录（右边补 `null`） |
| 右外连接 | `right join` | 匹配的记录 + 右表中不匹配的记录（左边补 `null`） |
| 全连接 | `full join` | ⚠️ **MySQL 不支持**；匹配记录 + 左表未匹配记录 + 右表未匹配记录 |

### 4.2 子查询

### 4.3 联合查询

- `union` / `union all`：将多个查询结果集合并
  - `union` 会自动去重

## 📌 本日重点回顾

1. **执行顺序**是 DQL 的核心考点：`from → where → group by → having → select → order by → limit`
2. `where` 不能用聚合函数，`having` 可以
3. 实际项目中优先使用**逻辑外键**而非物理外键，靠代码保证数据一致性
4. MySQL **不支持** `full join`，需要用 `union` 模拟全连接效果
