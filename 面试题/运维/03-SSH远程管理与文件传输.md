## 二、SSH 基本概念

SSH（Secure Shell）是用于安全远程登录等场景的加密协议，通常使用 TCP 22 端口。常见认证方式是密码认证和公钥认证。

| 项目 | 所在端 | 作用 |
| --- | --- | --- |
| 用户私钥 | 客户端 | 签名以证明用户身份，需妥善保管 |
| 用户公钥 | 服务端用户的 `~/.ssh/authorized_keys` | 验证用户签名 |
| 服务端主机密钥 | 服务端 | 向客户端证明服务器身份 |
| `known_hosts` | 客户端 | 保存已信任服务器的主机公钥信息 |

## 三、公钥认证流程

1. 客户端生成用户密钥对，将公钥安装到服务端目标用户的授权文件。
2. 建立 SSH 连接时，协商加密算法并完成密钥交换；客户端核验服务器主机密钥。
3. 客户端使用用户私钥对本次认证相关数据签名。
4. 服务端使用已授权的用户公钥验证签名，结合账户及服务策略决定是否允许登录。

> **原理校正：**原图中“服务端用用户公钥加密随机串、客户端解密并回传”不是现代 SSH 公钥认证的准确描述。应记住“私钥签名、公钥验签”。参考 [OpenSSH 服务端手册](https://man.openbsd.org/sshd.8)。

## 四、配置密钥登录

以下为整理后的示例，地址和用户名按实际环境替换。

```bash
# 服务端：安装、启动 SSH 服务（RHEL 系发行版示例）
dnf install -y openssh-server
systemctl enable --now sshd

# 客户端：生成密钥，并将公钥安装到服务端
ssh-keygen -t ed25519
ssh-copy-id ops@192.168.88.10
ssh ops@192.168.88.10
```

`ssh-copy-id` 通常在安装公钥时要求输入目标用户密码；公钥安装成功后，后续 SSH 登录可无需账户密码。若私钥设置了口令，仍可能提示解锁私钥，可结合 `ssh-agent` 使用。

首次连接可能提示确认主机指纹，应核对服务器身份。常见权限为 `~/.ssh` 目录 `700`、`authorized_keys` 文件 `600`，且所有者应正确。

## 五、执行远程命令

```bash
ssh ops@192.168.88.10 'hostname'
ssh ops@192.168.88.10 'cd /data && ls -lh'
```

| 分隔符 | 行为 |
| --- | --- |
| `;` | 前一条命令失败，仍继续后面的命令 |
| `&&` | 仅当前一条命令成功时才继续 |

外层单引号可避免本地 Shell 提前展开其中变量，具体引号写法取决于希望在哪端展开。

## 六、SCP 文件传输

SCP 是借助 SSH 连接进行文件复制的工具。远程路径写为 `用户@主机:/路径`。

```bash
scp app.conf ops@192.168.88.10:/tmp/
scp ops@192.168.88.10:/tmp/result.txt ./
scp -r ./config ops@192.168.88.10:/tmp/
scp -C archive.tar ops@192.168.88.10:/tmp/
```

`-r` 用于递归复制目录，`-C` 启用压缩。SSH 指定端口使用小写 `-p`，SCP 指定端口使用大写 `-P`。

## 七、故障排查与面试速记

排查顺序：**网络可达 → SSH 端口监听 → 防火墙 → 用户与密钥 → 文件权限 → 服务日志**。

```bash
ss -lntp
systemctl status sshd
journalctl -u sshd
ssh -v ops@192.168.88.10
```

- **免密登录靠什么？**客户端保留私钥，服务端保存授权公钥，认证时验签。
- **公钥和私钥哪个上传？**上传公钥，私钥留在客户端。
- **认证用户与验证服务器是一回事吗？**分别由用户密钥和服务器主机密钥承担。
- **SCP 与 rsync 的区别？**SCP 适合直接复制；rsync 提供更丰富的同步、差异传输与镜像选项。
