## 一、服务器标准化与快照

原图中的初始化项目包括静态 IP、规范主机名、SSH 密钥登录及 hosts 映射。SELinux 应按环境配置；原图中直接关闭的做法属于实验配置。

`/etc/hosts` 保存本地域名与 IP 的静态映射。是否优先于 DNS 取决于 `/etc/nsswitch.conf` 的 `hosts` 查询顺序及应用自身解析方式，不能一概而论。

完成标准化后可建立虚拟机快照，用于实验回退；快照不能替代独立备份。原图添加虚拟磁盘前先关闭虚拟机，按所用虚拟化平台操作。

## 二、磁盘管理核心流程

**识别磁盘 → 分区或创建逻辑卷 → 创建文件系统 → 挂载 → 配置持久挂载 → 验证。**

| 概念 | 含义 |
| --- | --- |
| 分区 | 将磁盘空间划分为多个逻辑区域 |
| 格式化 | 创建文件系统，用于组织文件与元数据 |
| 挂载 | 将文件系统接入某个目录，目录称为挂载点 |
| 卸载 | 断开文件系统与挂载点的关联 |
| LVM | 通过卷管理抽象组织存储，支持更灵活的容量管理 |
| RAID | 将多个磁盘组合，按级别提供性能、冗余或二者兼顾 |

## 三、分区表与文件系统

### 1. MBR 与 GPT

| 对比 | MBR | GPT |
| --- | --- | --- |
| 容量 | 常见 512 字节逻辑扇区下约 2 TiB 上限 | 支持远大于 MBR 的容量，仍有实现限制 |
| 分区数量 | 最多 4 个主分区表项，可通过扩展分区组织逻辑分区 | 常见默认 128 个分区表项，可调整，并非无限 |
| 原图工具 | `fdisk` | `parted` |

现代 `fdisk` 也支持 GPT，不能将工具与分区表类型绝对绑定。

### 2. ext4 与 XFS

二者都是常见 Linux 文件系统。原图以 ext4 和 XFS 对比不同代际系统的使用习惯；实际默认类型以安装器、版本和分区用途为准。

```bash
lsblk -f                              # 查看块设备、文件系统与挂载点
blkid                                 # 查看文件系统标识和 UUID
# 以下创建文件系统命令会覆盖目标文件系统结构，仅对确认的新分区执行
mkfs.ext4 /dev/sdb1
# 若选择 XFS，使用 mkfs.xfs /dev/sdb1；二者是替代选项
```

## 四、挂载与持久化

```bash
mkdir -p /data
mount /dev/sdb1 /data                  # 临时挂载
findmnt /data
umount /data                          # 也可按设备路径卸载
```

在 `/etc/fstab` 配置启动时挂载，通常优先使用 UUID 避免设备名变化。以下为 ext4 示例，UUID 需替换：

```fstab
UUID=替换为实际UUID /data ext4 defaults 0 2
```

六个字段依次为：设备、挂载点、文件系统类型、挂载选项、dump 标志、启动检查顺序。XFS 示例通常使用末尾 `0 0`，不要直接照搬 ext4 的检查设置。

编辑后检查条目与设备匹配，再执行 `mount -a` 并用 `findmnt`、`df -h` 验证；错误的 fstab 可能影响后续启动。卸载失败时先检查工作目录和占用进程。

## 五、LVM：PV → VG → LV → 文件系统

| 层次 | 名称 | 作用 |
| --- | --- | --- |
| PV | 物理卷 | 将磁盘或分区初始化为 LVM 可用的存储 |
| VG | 卷组 | 汇聚一个或多个 PV 的容量 |
| LV | 逻辑卷 | 从 VG 中分配空间，对上提供块设备 |

### 1. 创建与查看

以下仅为新磁盘实验流程，设备与名称按实际替换，不能对已有业务盘直接执行。

```bash
pvcreate /dev/sdb
pvdisplay /dev/sdb
vgcreate vg_data /dev/sdb
vgdisplay vg_data
lvcreate -L 10G -n lv_app vg_data
lvdisplay
```

创建 LV 后，仍需创建文件系统并挂载。

### 2. 扩容

```bash
pvcreate /dev/sdc
vgextend vg_data /dev/sdc
lvextend -L +5G /dev/vg_data/lv_app
```

**逻辑卷扩容与文件系统扩容是两个步骤。**上述操作只扩大 LV，随后根据文件系统选择：

```bash
resize2fs /dev/vg_data/lv_app            # ext4
# XFS 使用挂载点：xfs_growfs /data
```

LVM 的弹性不代表任意文件系统都支持在线缩容；XFS 不支持缩小文件系统。缩容必须单独规划，不能按扩容步骤反向执行。

## 六、RAID 常见级别

下表假设 N 块等容量磁盘，每块容量为 S，不计元数据及备用盘。

| 级别 | 机制 | 常见最少磁盘数 | 可用容量 | 容错要点 |
| --- | --- | --- | --- | --- |
| RAID 0 | 条带化 | 2 | N × S | 无冗余，任一盘故障可能导致阵列数据丢失 |
| RAID 1 | 镜像 | 2 | 常见单组为 S | 两盘镜像可损坏一盘；读性能可能改善，写入需维护镜像 |
| RAID 5 | 条带化 + 分布式单校验 | 3 | (N − 1) × S | 可容忍一盘故障，写入有校验开销 |
| RAID 10 | 镜像后条带化 | 常见为 4 | N × S ÷ 2 | 可容忍的故障取决于位置，同一镜像组全坏会丢数据 |

> **原图校正：**RAID 1 的读性能可能提升；RAID 5 写性能不能简单视为接近 RAID 0；RAID 10 也不是任意多盘故障都能容忍。RAID 提供的冗余不能代替备份。

### RAID 1 实验命令

```bash
dnf install -y mdadm
# 两块设备必须是确认可覆盖的实验盘
mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/nvme0n3 /dev/nvme0n4
cat /proc/mdstat
mdadm --detail /dev/md0
```

原图通过 `mdadm --detail --scan --verbose >> /etc/mdadm.conf` 保存阵列信息，并执行 `dracut --force` 更新 initramfs。实际应检查已有配置，避免反复追加重复条目；是否重建 initramfs 取决于发行版与启动依赖。阵列创建后还需创建文件系统、挂载和验证。

## 七、面试速记

- **分区、格式化、挂载分别做什么？**划空间、建文件系统、接入目录树。
- **永久挂载为什么使用 UUID？**降低设备枚举名称变化带来的影响。
- **LVM 扩容后 df 没变？**检查文件系统是否同步扩容，以及查看的挂载点是否正确。
- **RAID 5 能坏几块盘？**一块；重建期间需关注进一步故障风险。
- **RAID 10 能坏两块盘吗？**取决于是否落在同一镜像组，不能只看数量。
