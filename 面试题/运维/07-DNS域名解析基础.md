## 一、DNS 的作用

DNS（Domain Name System，域名系统）是分布式、分层的命名系统，可理解为网络中的电话簿。

| 功能 | 说明 |
| --- | --- |
| 正向解析 | 根据域名查询地址，如 A、AAAA 记录 |
| 反向解析 | 根据 IP 查询 PTR 记录；并非每个 IP 都有对应记录 |
| 多地址分流 | 同一域名可返回多个地址，但不自动等于完整的负载均衡和健康检查 |
| 简化配置 | 使用稳定名称，地址变更时集中更新记录，仍需考虑缓存 |

原图“使用域名，而不是使用域名”整理为“使用域名，而不是硬编码 IP”。

## 二、DNS 的层级与角色

| 角色 | 主要职责 |
| --- | --- |
| 根域名服务器 | 提供顶级域的委派信息 |
| 顶级域服务器 | 管理 `.com`、`.cn` 等顶级域下的委派 |
| 权威域名服务器 | 为其负责的区域提供权威记录 |
| 递归解析器 / 缓存服务器 | 接受客户端查询，代为查找并缓存结果 |

根、顶级域、权威服务器体现域名层级；递归解析器是查询角色，不宜机械地当作权威层级中的“第四层”。原图中的 `8.8.8.8` 是公共递归解析器的例子。

> **数字校正：**根服务器体系有 13 个命名的服务器标识，并非全球只有 13 台物理机器；它们通过多个实例提供服务。参考 [IANA 根服务器列表](https://www.iana.org/domains/root/servers)。

## 三、查询流程（补充）

以查询 `www.example.com` 为例：

1. 应用发起解析，本地解析流程可能使用 hosts、本地缓存或系统解析器，具体顺序依配置而定。
2. 本地无法命中时，向配置的递归解析器发起查询。
3. 递归解析器先查缓存；如未命中且需要从根查起，向根服务器获取 `.com` 委派。
4. 向 `.com` 顶级域服务器获取 `example.com` 的权威服务器信息。
5. 向权威服务器获取目标记录，必要时继续处理 CNAME 等结果。
6. 递归解析器返回结果，并按 TTL 等规则缓存。

**递归查询**要求被查询方代为完成解析并返回最终结果或错误；**迭代查询**可返回指向其他服务器的委派信息。常见模式为客户端向递归解析器递归查询，解析器向权威体系迭代查询。

## 四、常见记录（补充速记）

| 类型 | 用途 |
| --- | --- |
| A | 域名对应 IPv4 地址 |
| AAAA | 域名对应 IPv6 地址 |
| CNAME | 域名别名 |
| PTR | 反向查询记录 |
| NS | 指定区域的权威服务器 |
| MX | 指定邮件服务器 |

## 五、面试速记

- **正向和反向解析的区别？**域名查地址与地址查名称，记录分别维护，不自动互相生成。
- **改了 DNS 为什么没立即生效？**检查权威数据、递归缓存、本地缓存以及 TTL。
- **一个域名能对应多个 IP 吗？**可以，客户端的选择及流量分配并不必然均匀。
- **根服务器有多少台？**应区分 13 个命名标识与实际部署的多个服务实例。
- **递归服务器与权威服务器区别？**前者代查和缓存，后者对负责区域提供权威回答。
