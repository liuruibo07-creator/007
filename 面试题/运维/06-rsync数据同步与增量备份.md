## 一、rsync 是什么

rsync 用于本地和远程文件同步，可按选项保留权限、时间、所有者等属性。远程同步可借助 SSH 加密传输。

```bash
dnf install -y rsync
# SSH 远程同步通常要求源端、目标端都安装 rsync
```

## 二、增量同步原理

1. 通常先根据文件大小和修改时间快速判断是否需要传输。
2. 使用差异传输算法时，接收端针对已有文件计算分块校验信息，将块签名发送给发送端。
3. 发送端扫描源文件、匹配可复用数据块，发送变化数据和对已有数据的引用。
4. 接收端结合旧文件块和新数据重建文件。

> **原图校正：**接收端无需先把完整旧数据块连同校验和发送给源端。本地传输通常默认采用整文件传输；是否使用块级差异算法取决于传输方式和选项。参考 [rsync 官方手册](https://download.samba.org/pub/rsync/rsync.1)。

## 三、语法和常用选项

基本格式：`rsync [选项] 源路径... 目标路径`，可指定多个源路径，目标路径放在最后。

| 选项 | 含义 |
| --- | --- |
| `-a` | 归档模式，常用组合，包含递归及多项属性保留；并非任何场景都必须使用 |
| `-v` | 显示详细输出 |
| `-z` | 压缩传输，适合可压缩数据或受限链路，已压缩文件收益可能较低 |
| `-n` / `--dry-run` | 预演变更，不实际同步 |
| `--delete` | 删除接收端同步范围内、源端不存在的条目 |
| `-e ssh` | 指定使用 SSH 作为远程传输方式 |

`-a` 不包含所有元数据：硬链接、ACL、扩展属性分别需按需增加 `-H`、`-A`、`-X`；保留所有者等信息还受权限和文件系统能力限制。各选项定义见 [rsync 官方手册](https://download.samba.org/pub/rsync/rsync.1)。

## 四、源目录结尾斜杠的区别

以下假设目标 `/backup/` 已存在。

| 命令 | 结果 |
| --- | --- |
| `rsync -av /data/project /backup/` | 得到 `/backup/project/`，包含目录本身 |
| `rsync -av /data/project/ /backup/` | 将 project 内部内容直接放入 `/backup/` |

目录尾部 `/` 会影响目标结构，正式执行前可先使用 `-n` 查看结果。

## 五、常用同步示例

```bash
# 本地同步
rsync -av /data/ /backup/

# 推送到远端
rsync -avz -e ssh /data/ ops@192.168.88.20:/backup/

# 从远端拉取
rsync -avz -e ssh ops@192.168.88.20:/data/ /backup/

# 镜像同步：先预演，确认目标删除项
rsync -av --delete --dry-run /data/ /backup/
# 确认同步范围后，移除 --dry-run 才会实际执行
```

> `--delete` 会删除目标独有数据。镜像同步可能同步传播误删，若用于备份，应另行考虑版本保留或独立副本。

## 六、定时与实时同步

| 方案 | 触发方式 | 适用特点 |
| --- | --- | --- |
| rsync + crontab | 周期调度 | 简单，存在一个调度周期的延迟 |
| rsync + inotify | 监听文件系统事件后触发 | 更及时，需要处理事件风暴、合并与失败重试 |

下面仅为调度示例，SSH 认证和日志目录需事先配置：

```cron
*/10 * * * * /usr/bin/rsync -az /data/ ops@192.168.88.20:/backup/ >> /var/log/rsync-backup.log 2>&1
```

inotify 负责发现事件，rsync 负责同步；组合使用不意味着自动具备完整的一致性和容错能力。

## 七、面试速记

- **为什么 rsync 适合重复同步？**可快速比较文件并在适用场景只传变化数据。
- **源目录加不加斜杠有什么区别？**加 `/` 同步内容，不加通常保留该目录层级。
- **-a 能完整保留一切吗？**不能；ACL、扩展属性、硬链接等需额外选项及权限。
- **同步就是备份吗？**还需考虑历史版本、误删恢复、独立副本及恢复验证。
