## 一、运维职责与软件生命周期

**运维的目标：通过技术手段，保障企业 IT 系统持续、稳定、安全地运行。**

| 分类 | 主要关注点 |
| --- | --- |
| 软件运维 | 软件部署与更新、数据备份与恢复、监控与报警、故障排查与处理 |
| 硬件运维 | 服务器、磁盘等硬件设备的运行维护 |
| 网络运维 | 网络连通性、网络设备与通信质量 |

软件生命周期：**需求分析 → 系统设计 → 系统开发 → 系统测试 → 系统上线 → 系统运维**。运维需参与上线准备和运行保障。

“上线”指将系统部署到生产环境。开发环境用于开发，测试环境用于验证，生产环境承载真实业务。

## 二、网络通信基础

### 1. IP、端口、协议

| 要素 | 作用 | 记忆要点 |
| --- | --- | --- |
| IP 地址 | 标识网络中的接口及其网络位置 | 同一网络中应避免地址冲突 |
| 端口 | 配合 IP 和传输层协议标识通信端点 | 范围为 0～65535 |
| 协议 | 规定通信双方遵守的规则 | 如 TCP、UDP、HTTP |
| 域名 | 用便于记忆的名称访问网络资源 | 通常通过 DNS 查询地址 |

IPv4 常用点分十进制表示；IPv6 常用冒分十六进制表示。公网地址可在公网路由，私网地址不能直接在公网路由，通常通过 NAT 或代理访问互联网。

> **概念校正：**端口不能脱离绑定地址和协议讨论。同一主机的 TCP 53 与 UDP 53 可以同时使用；同一协议、同一本地地址和端口的监听通常存在冲突，也有端口复用等例外。

### 2. 常见协议

| 协议 | 所在层 | 特点 |
| --- | --- | --- |
| TCP | 传输层 | 面向连接，提供可靠、有序的字节流传输 |
| UDP | 传输层 | 无连接，不保证送达与顺序 |
| HTTP | 应用层 | 超文本传输协议；HTTP/1.1 和 HTTP/2 通常基于 TCP，HTTP/3 基于 QUIC/UDP |

## 三、Linux 与发行版

Linux 广泛用于服务器，也用于桌面和嵌入式设备。**内核**负责进程、内存、设备等底层管理；**发行版**在内核基础上组合系统工具、软件包与安装维护体系。

原图涉及 RHEL、CentOS Linux、CentOS Stream：可按“商业企业发行版、历史下游重构版、位于后续 RHEL 更新之前的持续交付分支”理解。CentOS Linux 与 CentOS Stream 应区分，安装时应核对具体版本及支持周期。

## 四、VMware 与实验环境安装

VMware 可虚拟硬件，在虚拟机中安装所需操作系统。原图中的实验配置整理如下：

| 项目 | 原图建议 / 整理说明 |
| --- | --- |
| 安装路径 | 使用统一目录，尽量避免中文路径引发兼容性问题 |

## 五、关机与重启

| 命令 | 作用 |
| --- | --- |
| `reboot` | 发起重启 |
| `shutdown -r +5` | 5 分钟后重启 |
| `shutdown -h +5` | 5 分钟后关机 |
| `shutdown -h now` | 立即关机 |
| `shutdown -c` | 取消计划中的关机或重启 |

未指定时间的 `shutdown` 通常默认为一分钟后执行。计划操作前应考虑业务影响。

## 六、面试速记

- **运维做什么？**部署、备份、监控、故障处理，目标是稳定、安全、持续运行。
- **上线是什么？**将系统部署到生产环境，并完成验证与运行保障。
- **IP 和端口分别解决什么？**IP 标识网络位置，端口配合协议标识通信端点。
- **虚拟机安装后先做什么？**确认网络、主机名、SSH、时间与基本访问控制。
