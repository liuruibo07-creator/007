# Java SE 学生管理系统开发计划

> 项目类型：控制台 C/S 学生管理系统  
> 开发工具：IntelliJ IDEA  
> Java 版本：JDK 17  
> 数据库：MySQL 8.x  
> 通信方式：TCP Socket + `DataInputStream` / `DataOutputStream`  
> 服务端并发方式：一个客户端连接对应一个处理线程  

---

## 1. 项目目标

使用纯 Java SE 在 IntelliJ IDEA 中开发一个控制台学生管理系统。系统分为客户端和服务端：

- 客户端负责登录、显示菜单、读取用户输入、发送 TCP 请求和显示结果。
- 服务端负责身份验证、业务校验、并发处理客户端请求，并通过 JDBC 访问 MySQL。
- MySQL 负责持久化管理员和学生数据。
- Git 负责版本管理。

第一版只提供管理员角色，支持：

1. 管理员登录。
2. 新增学生。
3. 按数据库主键查询学生。
4. 按学号精确查询学生。
5. 按姓名或班级模糊查询学生。
6. 分页显示全部学生。
7. 按学号、姓名、班级或创建时间排序。
8. 修改学生信息。
9. 删除学生，删除前要求确认。
10. 安全退出。
11. 同时运行多个客户端。

## 3. 总体架构

```text
┌──────────────────────────┐
│ Console Client           │
│ 菜单、输入、结果展示       │
└────────────┬─────────────┘
             │ TCP 长连接
             │ DataInputStream / DataOutputStream
             ▼
┌──────────────────────────┐
│ Multithreaded Server     │
│ ServerSocket : 8888      │
│ 每个客户端一个处理线程     │
├──────────────────────────┤
│ Service                  │
│ 登录、校验、业务规则       │
├──────────────────────────┤
│ DAO + JDBC               │
│ PreparedStatement        │
└────────────┬─────────────┘
             │ JDBC
             ▼
┌──────────────────────────┐
│ MySQL 8.x                │
│ admin / student          │
└──────────────────────────┘
```

重要约束：

- 客户端不能直接连接 MySQL。
- 数据库账号和密码只保存在服务端本地配置文件。
- 服务端不能在多个线程之间共享同一个 JDBC `Connection`。
- 每次数据库操作独立获取并关闭连接。
- 客户端登录后保持 TCP 长连接，直到主动退出或连接异常。

## 7. 创建数据库

在 `sql/schema.sql` 中编写：

```sql
CREATE DATABASE IF NOT EXISTS student_management
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

USE student_management;

CREATE TABLE IF NOT EXISTS admin (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL,
    password_hash VARCHAR(64) NOT NULL,
    salt VARCHAR(64) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_admin_username UNIQUE (username)
);

CREATE TABLE IF NOT EXISTS student (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    student_no VARCHAR(30) NOT NULL,
    name VARCHAR(50) NOT NULL,
    gender VARCHAR(10) NOT NULL,
    birth_date DATE NULL,
    phone VARCHAR(30) NULL,
    email VARCHAR(100) NULL,
    class_name VARCHAR(100) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
        ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT uk_student_no UNIQUE (student_no),
    CONSTRAINT chk_student_gender
        CHECK (gender IN ('男', '女', '其他'))
);

CREATE INDEX idx_student_name ON student(name);
CREATE INDEX idx_student_class_name ON student(class_name);
```

执行：

```shell
mysql -u root -p < sql/schema.sql
```

检查：

```sql
USE student_management;
SHOW TABLES;
DESC admin;
DESC student;
```

应能看到 `admin` 和 `student` 两张表。

## 8. 配置 JDBC

### 8.1 配置文件

创建 `config/db.properties.example`：

```properties
db.url=jdbc:mysql://127.0.0.1:3306/student_management?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
db.username=填写你的数据库用户名
db.password=填写你的数据库密码
```

复制为 `config/db.properties`，只修改副本中的真实账号密码。真实配置不能提交到 Git。

### 8.2 `DatabaseConfig`

职责：

- 从 `config/db.properties` 加载配置。
- 检查 `db.url`、`db.username`、`db.password` 是否存在。
- 配置缺失时抛出说明清楚的异常。

建议接口：

```java
public final class DatabaseConfig {
    public static String getUrl();
    public static String getUsername();
    public static String getPassword();
}
```

### 8.3 `DatabaseUtil`

```java
public final class DatabaseUtil {
    private DatabaseUtil() {
    }

    public static Connection getConnection() throws SQLException {
        return DriverManager.getConnection(
                DatabaseConfig.getUrl(),
                DatabaseConfig.getUsername(),
                DatabaseConfig.getPassword()
        );
    }
}
```

Connector/J 8.x 支持 JDBC 自动加载驱动，一般不需要手动调用 `Class.forName`。

### 8.4 JDBC 连接测试

创建临时的 `main` 方法：

```java
try (Connection connection = DatabaseUtil.getConnection()) {
    System.out.println("数据库连接成功：" + !connection.isClosed());
} catch (SQLException e) {
    System.err.println("数据库连接失败：" + e.getMessage());
}
```

连接成功后删除临时入口，保留可复用的工具类。

## 10. 定义 TCP Data 流协议

### 10.1 操作码

`Protocol` 中定义：

```java
public static final int LOGIN = 1;
public static final int ADD_STUDENT = 2;
public static final int GET_BY_ID = 3;
public static final int GET_BY_STUDENT_NO = 4;
public static final int SEARCH_STUDENTS = 5;
public static final int UPDATE_STUDENT = 6;
public static final int DELETE_STUDENT = 7;
public static final int LIST_STUDENTS = 8;
public static final int LOGOUT = 9;
```

响应码：

```java
public static final int OK = 0;
public static final int INVALID_REQUEST = 400;
public static final int UNAUTHORIZED = 401;
public static final int NOT_FOUND = 404;
public static final int DUPLICATE_STUDENT_NO = 409;
public static final int SERVER_ERROR = 500;
```

排序字段代码：

```java
public static final int SORT_STUDENT_NO = 1;
public static final int SORT_NAME = 2;
public static final int SORT_CLASS_NAME = 3;
public static final int SORT_CREATED_AT = 4;
```

排序方向：

```java
public static final int SORT_ASC = 1;
public static final int SORT_DESC = 2;
```

### 10.2 通用响应格式

所有响应严格按以下顺序写入和读取：

```text
boolean success
int resultCode
String message
int recordCount
recordCount 条 Student 数据
```

没有学生记录时必须写入 `recordCount = 0`。

### 10.3 字符串与可空字段

- 普通非空字符串：`writeUTF` / `readUTF`。
- 可空字符串：先写 `boolean`，存在时再写 `UTF`。
- 可空日期：先写 `boolean`，存在时写 ISO 日期文本，如 `2007-09-01`。
- 时间使用 ISO 文本，如 `2026-07-24T10:30:00`。

示例：

```java
private static void writeNullableString(
        DataOutputStream out, String value) throws IOException {
    out.writeBoolean(value != null);
    if (value != null) {
        out.writeUTF(value);
    }
}

private static String readNullableString(
        DataInputStream in) throws IOException {
    return in.readBoolean() ? in.readUTF() : null;
}
```

### 10.4 Student 的字段顺序

所有操作必须使用完全相同的顺序：

```text
long id
String studentNo
String name
String gender
nullable LocalDate birthDate
nullable String phone
nullable String email
String className
nullable LocalDateTime createdAt
nullable LocalDateTime updatedAt
```

新增请求中的 `id` 写 `0`，创建和更新时间写空。更新请求必须携带数据库主键。

### 10.5 各请求载荷

| 操作 | 客户端在操作码后写入 |
|---|---|
| LOGIN | `username`、`password` |
| ADD_STUDENT | 一条 Student |
| GET_BY_ID | `long id` |
| GET_BY_STUDENT_NO | `String studentNo` |
| SEARCH_STUDENTS | `String keyword`、`int page`、`int pageSize` |
| UPDATE_STUDENT | 一条包含 ID 的 Student |
| DELETE_STUDENT | `long id` |
| LIST_STUDENTS | `int page`、`int pageSize`、`int sortField`、`int sortDirection` |
| LOGOUT | 无 |

每次写完一个完整请求后调用 `flush()`。读取端必须按照协议顺序读取，任何一端都不能随意增加或调整字段。

## 11. 密码与管理员初始化

### 11.1 `PasswordUtil`

仅使用 Java SE：

- `SecureRandom` 生成随机盐。
- `MessageDigest.getInstance("SHA-256")` 计算摘要。
- `HexFormat` 将字节转为十六进制字符串。
- 计算内容为 `salt + password` 的 UTF-8 字节。

建议接口：

```java
public static String generateSalt();
public static String hash(String password, String salt);
public static boolean matches(
        String rawPassword, String salt, String expectedHash);
```

限制：

- 密码不能为空。
- 初始化密码建议不少于 8 个字符。
- 服务端日志不能打印用户密码。

### 11.2 `AdminInitializer`

提供独立的 `main` 方法：

1. 从控制台读取管理员用户名。
2. 使用 `System.console().readPassword()` 读取密码。
3. IDEA 中 `System.console()` 可能为空，此时用 `Scanner` 作为备用方式，并提示输入将可见。
4. 生成盐和摘要。
5. 使用 `PreparedStatement` 插入 `admin` 表。
6. 如果用户名重复，显示“管理员已存在”。

运行一次，创建例如 `admin` 的管理员账号，然后再启动服务器。

## 12. DAO 层

### 12.1 `AdminDao`

接口：

```java
public Optional<AdminCredential> findByUsername(String username)
        throws SQLException;

public boolean create(
        String username, String passwordHash, String salt)
        throws SQLException;
```

查询 SQL：

```sql
SELECT id, username, password_hash, salt
FROM admin
WHERE username = ?
```

### 12.2 `StudentDao`

建议接口：

```java
public Student insert(Student student) throws SQLException;
public Optional<Student> findById(long id) throws SQLException;
public Optional<Student> findByStudentNo(String studentNo)
        throws SQLException;
public List<Student> search(
        String keyword, int offset, int limit) throws SQLException;
public List<Student> list(
        int offset, int limit, int sortField, int sortDirection)
        throws SQLException;
public boolean update(Student student) throws SQLException;
public boolean deleteById(long id) throws SQLException;
public boolean existsByStudentNo(String studentNo) throws SQLException;
public boolean existsByStudentNoExceptId(
        String studentNo, long excludedId) throws SQLException;
```

### 12.3 DAO 编码规则

1. 所有值都通过 `PreparedStatement` 参数传入。
2. 每个方法使用 try-with-resources。
3. 不缓存或共享 `Connection`。
4. DAO 不负责打印控制台菜单。
5. DAO 不把 `SQLException` 转换成模糊的成功或失败。
6. 用一个私有方法把 `ResultSet` 转成 `Student`。

示例：

```java
private Student mapStudent(ResultSet rs) throws SQLException {
    Student student = new Student();
    student.setId(rs.getLong("id"));
    student.setStudentNo(rs.getString("student_no"));
    student.setName(rs.getString("name"));
    student.setGender(rs.getString("gender"));

    Date birthDate = rs.getDate("birth_date");
    student.setBirthDate(
            birthDate == null ? null : birthDate.toLocalDate());

    student.setPhone(rs.getString("phone"));
    student.setEmail(rs.getString("email"));
    student.setClassName(rs.getString("class_name"));
    student.setCreatedAt(
            rs.getTimestamp("created_at").toLocalDateTime());
    student.setUpdatedAt(
            rs.getTimestamp("updated_at").toLocalDateTime());
    return student;
}
```

### 12.4 分页与安全排序

分页：

```text
offset = (page - 1) * pageSize
```

服务端必须保证：

- `page >= 1`
- `1 <= pageSize <= 100`

列名不能通过 `?` 占位符传入，因此只能用服务端白名单映射：

```java
String orderBy = switch (sortField) {
    case Protocol.SORT_STUDENT_NO -> "student_no";
    case Protocol.SORT_NAME -> "name";
    case Protocol.SORT_CLASS_NAME -> "class_name";
    case Protocol.SORT_CREATED_AT -> "created_at";
    default -> throw new IllegalArgumentException("非法排序字段");
};

String direction = switch (sortDirection) {
    case Protocol.SORT_ASC -> "ASC";
    case Protocol.SORT_DESC -> "DESC";
    default -> throw new IllegalArgumentException("非法排序方向");
};
```

只有白名单产生的列名和方向可以拼接进 SQL。页大小和偏移量仍使用参数：

```sql
SELECT id, student_no, name, gender, birth_date,
       phone, email, class_name, created_at, updated_at
FROM student
ORDER BY <服务端白名单列> <服务端白名单方向>
LIMIT ? OFFSET ?
```

## 13. Service 层

### 13.1 `AuthService`

流程：

1. 检查用户名和密码是否为空。
2. 调用 `AdminDao.findByUsername`。
3. 用户不存在时返回登录失败。
4. 使用 `PasswordUtil.matches` 比较密码。
5. 不向客户端透露是用户名错误还是密码错误，统一提示“用户名或密码错误”。

### 13.2 `ValidationUtil`

固定校验规则：

- 学号：必填，去除首尾空格后长度 1～30。
- 姓名：必填，长度 1～50。
- 性别：只能是 `男`、`女`、`其他`。
- 班级：必填，长度 1～100。
- 出生日期：为空或合法 ISO 日期，且不能晚于当前日期。
- 电话：为空或由数字、空格、`+`、`-` 组成，长度不超过 30。
- 邮箱：为空，或包含一个位于中间的 `@`，长度不超过 100。
- 主键：查询、修改和删除时必须大于 0。
- 页码：必须大于等于 1。
- 每页数量：必须在 1～100。

校验失败应返回明确提示，不进入 DAO。

### 13.3 `StudentService`

职责：

- 统一清理字符串首尾空格。
- 执行业务校验。
- 新增前检查学号是否重复。
- 修改前检查学生是否存在。
- 修改学号时排除当前学生 ID 后再检查重复。
- 将数据库唯一约束异常转换为“学号已存在”。
- 将不存在的记录转换为 404 响应。
- 将成功、校验失败和数据库异常转换为协议响应。

## 14. 多线程服务端

### 14.1 `ServerMain`

基本流程：

```java
public static void main(String[] args) {
    int port = 8888;
    try (ServerSocket serverSocket = new ServerSocket(port)) {
        System.out.println("学生管理服务器已启动，端口：" + port);

        while (true) {
            Socket socket = serverSocket.accept();
            Thread thread = new Thread(
                    new ClientHandler(socket),
                    "client-" + socket.getRemoteSocketAddress()
            );
            thread.start();
        }
    } catch (IOException e) {
        System.err.println("服务器启动或运行失败：" + e.getMessage());
    }
}
```

### 14.2 `ClientHandler`

每个 `ClientHandler`：

1. 只管理一个 Socket。
2. 为该 Socket 创建输入流和输出流。
3. 保存本连接的 `authenticated` 状态，初始为 `false`。
4. 循环读取操作码。
5. `LOGIN` 验证成功后将 `authenticated` 设置为 `true`。
6. 登录前只允许 `LOGIN` 和 `LOGOUT`。
7. 其他操作通过 `switch` 分发。
8. `LOGOUT` 响应成功后结束循环。
9. 客户端异常断开时只关闭当前连接。

伪代码：

```java
while (running) {
    int operation;
    try {
        operation = in.readInt();
    } catch (EOFException e) {
        break;
    }

    if (!authenticated
            && operation != Protocol.LOGIN
            && operation != Protocol.LOGOUT) {
        ProtocolCodec.writeResponse(
                out, false, Protocol.UNAUTHORIZED,
                "请先登录", List.of());
        continue;
    }

    switch (operation) {
        case Protocol.LOGIN -> handleLogin(in, out);
        case Protocol.ADD_STUDENT -> handleAdd(in, out);
        case Protocol.GET_BY_ID -> handleGetById(in, out);
        case Protocol.GET_BY_STUDENT_NO ->
                handleGetByStudentNo(in, out);
        case Protocol.SEARCH_STUDENTS -> handleSearch(in, out);
        case Protocol.UPDATE_STUDENT -> handleUpdate(in, out);
        case Protocol.DELETE_STUDENT -> handleDelete(in, out);
        case Protocol.LIST_STUDENTS -> handleList(in, out);
        case Protocol.LOGOUT -> running = false;
        default -> writeInvalidRequest(out);
    }
}
```

### 14.3 服务端异常处理

- `EOFException`：客户端正常关闭或突然断开，结束当前线程。
- `SocketException`：记录客户端连接中断，不停止主服务器。
- `IllegalArgumentException`：返回 400。
- `SQLException`：服务端记录错误详情，客户端只收到安全提示。
- 未知操作码：返回 400，但可以继续读取下一次请求。
- 未知运行时异常：返回 500，然后根据流状态决定是否关闭连接。

日志中可以记录时间、线程名、客户端地址、操作码和结果，但不能记录密码。

### 15.4 输入处理

不要直接用 `Scanner.nextInt()` 后再调用 `nextLine()`，否则容易跳过输入。统一使用：

```java
String input = scanner.nextLine().trim();
```

需要数字时再使用 `Integer.parseInt` 或 `Long.parseLong`，并捕获 `NumberFormatException`。

日期使用：

```java
LocalDate.parse(input);
```

输入为空时表示可选字段为 `null`。修改页面可以用“直接回车保留原值”的方式，先查询并显示旧记录，再构造完整的新记录发送给服务端。

4. 只有忽略大小写等于 `Y` 时才发送删除请求。
5. 取消时不能向服务端发送删除操作。

## 16. 推荐实现顺序

严格按以下顺序编码，可以减少同时出现大量错误：

### 第一步：工程和数据库

- 创建目录和包。
- 配置 JDK 17。
- 添加 Connector/J。
- 执行 `schema.sql`。
- 写 JDBC 配置和连接测试。

### 第二步：公共代码

- 完成 `Student`。
- 完成 `Protocol`。
- 完成 `ProtocolCodec`。
- 用内存流验证一条 Student 写入后能按相同内容读回。

### 第三步：密码与管理员

- 完成 `PasswordUtil`。
- 完成 `AdminDao`。
- 完成 `AdminInitializer`。
- 创建初始管理员并用 SQL 检查。

### 第四步：学生 DAO

- 依次实现新增、单条查询、修改、删除。
- 再实现模糊查询、分页和排序。
- 每完成一个方法，先用独立控制台入口验证 SQL。

### 第五步：Service

- 完成校验工具。
- 完成登录业务。
- 完成学生业务和错误转换。

### 第六步：服务端

- 先实现监听和连接日志。
- 再实现登录。
- 然后逐个增加学生操作。
- 最后测试多个客户端同时连接。

### 第七步：客户端

- 先实现连接与登录。
- 再实现菜单循环。
- 逐个实现新增、查询、修改、删除、分页和退出。

### 第八步：收尾

- 执行完整测试清单。
- 删除临时测试入口或放入明确的测试包。
- 补充 README。
- 检查 Git 中没有数据库密码。
