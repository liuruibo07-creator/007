## 一、继承 — 父类成员的继承与使用

子类继承父类后，对父类三种成员的继承规则各不相同：

| 成员类型 | 能否继承 | 能否使用 |
|----------|----------|----------|
| **构造方法** | ❌ 无论私有与否，**都不能继承** | ✅ 可以通过 `super()` 调用非私有构造 |
| **成员变量** | ✅ 无论私有与否，**都可以继承** | 只能使用**非私有**的成员变量 |
| **成员方法** | 只继承**虚方法** | 只能使用**虚方法** |

> 💡 "继承"和"使用"是两件事：私有成员可以被继承（存在于对象内存中），但不能被直接使用（访问权限限制）。

## 二、子类对象的内存分析

子类对象创建时，JVM 的内存分配遵循以下三条规律：

| 规律 | 说明 |
|------|------|
| **① 字节码加载顺序** | 先加载**父类**字节码文件，再加载**子类**字节码文件 |
| **② 对象内容** | 子类对象由父类和子类的字节码共同创建，**既包含父类属性，也包含子类属性** |
| **③ 对象数量** | 堆内存中**只有一个对象**，即子类对象（不存在独立的父类对象） |

```
      方法区
┌─────────────────┐
│  Animal.class   │  ← 先加载父类
│  Dog.class      │  ← 后加载子类
└─────────────────┘

      堆内存（只有一个对象）
┌──────────────────────────┐
│       Dog 对象            │
│  [父类属性] name = null   │
│  [父类属性] age  = 0      │
│  [子类属性] color = null  │
│  类地址 → Dog.class       │
└──────────────────────────┘
```

## 三、虚方法与虚方法表

### 3.1 什么是虚方法

满足以下**三个条件**的方法，才是虚方法：

| 条件 | 说明 |
|------|------|
| 非 `private` | 不能被私有修饰 |
| 非 `static` | 不能是静态方法 |
| 非 `final` | 不能是最终方法 |

> 只有虚方法才能被子类**继承和重写**。

---

### 3.2 虚方法表

JVM 在**类加载时**，会为每个类生成一张**虚方法表**，用于快速查找方法。

```
父类虚方法表：
┌──────────┐
│  eat()   │
│  sleep() │
│  toString() (来自 Object) │
└──────────┘

子类虚方法表（= 父类虚方法表 + 自己的虚方法）：
┌──────────┐
│  eat()   │ ← 继承自父类
│  sleep() │ ← 继承自父类
│  toString() │
│  bark()  │ ← 子类自己的虚方法
└──────────┘
```

**查找规则：** 子类对象访问方法时，**只需查自己的虚方法表**，效率更高。

## 四、父子关系下变量与方法的访问特点

### 核心原则：就近原则

> **谁离当前代码最近，就代表谁。**

| 写法 | 查找起点 | 说明 |
|------|----------|------|
| `name` | **局部变量** | 先找局部变量，没有再找成员变量 |
| `this.name` | **子类成员变量** | 明确指向当前对象（子类）的成员变量 |
| `super.name` | **父类成员变量** | 明确指向父类的成员变量 |

```java
public class Dog extends Animal {
    String name = "旺财";   // 子类成员变量

    public void show() {
        String name = "小黑";    // 局部变量

        System.out.println(name);        // → "小黑"  (局部变量)
        System.out.println(this.name);   // → "旺财"  (子类成员变量)
        System.out.println(super.name);  // → 父类中的 name 值
    }
}
```

## 五、方法重写（Override）

### 5.1 什么是方法重写

> 在子类中**重新定义一个与父类完全相同签名的方法**，重写后的方法会**覆盖**父类中的方法。（也称为**方法覆盖**）

```java
// 父类
public class Animal {
    public String toString() {
        return "Animal 对象";
    }
}

// 子类重写
public class Dog extends Animal {
    @Override
    public String toString() {
        return "Dog{name=" + name + ", age=" + age + "}";
    }
}
```

---

### 5.2 方法重写的四条细节

| 细节 | 说明 |
|------|------|
| **`@Override` 注解** | 用于**校验重写语法格式**是否正确，强烈建议加上 |
| **权限修饰符** | 子类方法的权限**大于或等于**父类方法（不能缩小访问范围） |
| **返回值类型** | 子类方法的返回值类型**小于或等于**父类方法（引用类型：父类算大，子类算小） |
| **非虚方法不能重写** | `private`、`static`、`final` 修饰的方法不是虚方法，**不能被重写** |

---

### 5.3 应用场景

**子类对父类的方法不满意时，进行重写。** 最典型的场景：

**重写 `Object` 类中的 `toString()` 方法：**

| 步骤 | 说明 |
|------|------|
| ① 打印对象实际调用的是 `toString()` 方法的返回值 | `System.out.println(obj)` 等价于 `System.out.println(obj.toString())` |
| ② `Object` 默认的 `toString()` 返回的是**地址值** | 如 `Dog@1b6d3586` |
| ③ 自定义类通常需要重写 `toString()`，返回**属性值** | 如 `Dog{name=旺财, age=3}` |

```java
// IDEA 快捷键：Alt + Insert → toString() 自动生成
@Override
public String toString() {
    return "Dog{name=" + name + ", age=" + age + "}";
}
```

## 六、父子关系下构造方法的访问特点

### 核心规则

> **所有子类构造方法，都会先访问父类构造方法，再执行自己的构造方法体。**

### 为什么这样设计

> 子类对象中既包含父类属性也包含子类属性，而**父类属性只有父类的构造方法知道如何正确初始化**，因此必须先调用父类构造。

### 显式与隐式调用

```java
public class Dog extends Animal {

    // 如果不手动写 super()，系统会自动补上 super() 调用父类无参构造
    public Dog() {
        super();           // 可以省略，系统自动添加
        System.out.println("Dog 无参构造");
    }

    public Dog(String name, int age, String color) {
        super(name, age);  // 手动调用父类有参构造（必须写在第一行）
        this.color = color;
    }
}
```

> ⚠️ `super()` 调用**必须写在子类构造方法的第一行**。

---

## 七、子类构造方法的定义

子类构造方法建议同时提供以下两种形式：

| 构造类型 | 说明 |
|----------|------|
| **无参构造** | 调用 `super()` 访问父类无参构造 |
| **全参构造** | 参数**同时包含父类属性和子类属性**，通过 `super(父类参数)` 初始化父类部分 |

```java
public class Animal {
    private String name;
    private int age;

    public Animal() {}
    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

public class Dog extends Animal {
    private String color;

    // 无参构造
    public Dog() {
        super();
    }

    // 全参构造（包含父类属性 + 子类属性）
    public Dog(String name, int age, String color) {
        super(name, age);      // ① 先初始化父类属性
        this.color = color;    // ② 再初始化子类属性
    }
}
```

## 八、this 与 super 总结

| 关键字 | 本质 | 指向 |
|--------|------|------|
| `this` | 子类对象的**引用** | 当前子类对象 |
| `super` | 父类**存储空间的标识** | 可理解为父类对象的引用（但并不存在独立的父类对象） |

| 使用场景 | `this` | `super` |
|----------|--------|---------|
| 访问成员变量 | `this.变量名` → 本类成员变量 | `super.变量名` → 父类成员变量 |
| 调用成员方法 | `this.方法名()` → 本类方法 | `super.方法名()` → 父类方法 |
| 调用构造方法 | `this()` → 本类其他构造方法 | `super()` → 父类构造方法 |

## 九、多态

### 9.1 什么是多态

**多态**是**面向对象三大特征之一**，描述的是一种对象的多种状态，体现为**对象多态**和**行为多态**。

---

### 9.2 多态的三个前提

| 前提 | 说明 |
|------|------|
| **① 有继承关系** | 子类继承父类 |
| **② 父类引用指向子类对象** | `Animal a = new Dog();` |
| **③ 有方法重写** | 子类重写了父类的方法 |

```java
Animal a = new Dog();   // 父类引用指向子类对象（多态写法）
a.eat();                // 运行时调用的是 Dog 的 eat() 方法
```

---

### 9.3 多态下成员的访问特点

| 成员类型 | 编译看 | 运行看 | 说明 |
|----------|--------|--------|------|
| **成员变量** | 父类 | 父类 | 变量无多态，编译运行都看父类 |
| **成员方法** | 父类 | **子类** | 方法有多态，运行时执行子类重写后的方法 |

```java
Animal a = new Dog();
System.out.println(a.name);  // 编译运行都看 Animal（父类）的 name
a.eat();                     // 编译看 Animal，运行执行 Dog 重写的 eat()
```

---

### 9.4 多态的好处

> **可以定义通用方法，提高程序的扩展性。**

**通用方法：** 方法的形参类型是**父类类型**，则可以接受所有子类对象。

```java
// 通用方法：形参是父类 Animal，传入任意子类都可以
public static void animalEat(Animal a) {
    a.eat();   // 实际运行的是各自子类的 eat()
}

// 调用：传入任意子类对象
animalEat(new Dog());   // Dog 的 eat()
animalEat(new Cat());   // Cat 的 eat()
animalEat(new Bird());  // Bird 的 eat()
```

---

### 9.5 多态的弊端

> **不能访问子类特有的成员。**（编译时只能看到父类的成员）

```java
Animal a = new Dog();
a.bark();   // ❌ 编译报错：Animal 中没有 bark() 方法
```

---

### 9.6 引用类型转换

#### 向上转型（自动，安全）

```java
Animal a = new Dog();   // 小类型（Dog）→ 大类型（Animal），自动完成
```

#### 向下转型（强制，有风险）

```java
Animal a = new Dog();
Dog d = (Dog) a;        // 大类型（Animal）→ 小类型（Dog），需强制转换
d.bark();               // ✅ 可以访问子类特有方法
```

#### 风险与避免

| 风险 | 解决方案 |
|------|----------|
| 强制类型转换可能引发 `ClassCastException`（类型转换异常） | 转换前用 **`instanceof`** 先进行判断 |

```java
Animal a = new Dog();

// instanceof 判断：a 是否是 Dog 类型的实例
if (a instanceof Dog) {
    Dog d = (Dog) a;
    d.bark();    // ✅ 安全调用
}
```

## 十、final 关键字

### 10.1 是什么

`final` 是 Java 中的一个**修饰符**，表示"**最终的**"，可以修饰**类、方法、变量**。

---

### 10.2 修饰不同目标的特点

| 修饰目标 | 效果 |
|----------|------|
| **修饰类** | 该类**不能再被继承** |
| **修饰方法** | 该方法**不能再被重写** |
| **修饰变量** | 该变量**不能再被赋值**，变为**常量** |

```java
// final 修饰类
public final class String { }      // String 类不能被继承

// final 修饰方法
public final void show() { }       // 子类不能重写 show()

// final 修饰变量（常量）
final int MAX_SIZE = 100;          // MAX_SIZE 不能再被赋值
```

---

### 10.3 常量的补充说明

**作用：** 提高代码的**可读性**和**可维护性**。

**命名规范：** 全部**大写**，多个单词之间用 **`_`** 分隔。

```java
// 常量命名规范示例
public static final int MAX_STUDENT_NUM = 50;
public static final String DEFAULT_NAME = "未知";
public static final double PI = 3.14159265358979;
```

## 十一、抽象类

### 11.1 什么是抽象类与抽象方法

| 概念 | 定义 | 语法 |
|------|------|------|
| **抽象类** | 被 `abstract` 修饰的类 | `public abstract class 类名 {}` |
| **抽象方法** | 被 `abstract` 修饰的方法 | `public abstract 返回值类型 方法名();`（**没有方法体**） |

```java
public abstract class Animal {

    // 抽象方法：没有方法体，强制要求子类实现
    public abstract void eat();
    public abstract void sleep();

    // 普通方法：抽象类中也可以定义
    public void breathe() {
        System.out.println("呼吸...");
    }
}
```

---

### 11.2 四条重要注意事项

| 序号 | 注意事项 |
|------|----------|
| **① 可以无抽象方法** | 抽象类中**可以没有**抽象方法，但**有抽象方法的类一定是抽象类** |
| **② 不能创建对象** | 抽象类**不能 `new` 出对象**，其定位是作为**父类**使用 |
| **③ 本质仍是 Java 类** | 抽象类中**能定义的内容与普通类相同**（成员变量、构造方法、普通方法等） |
| **④ 子类的两种选择** | 子类要么**把自己也声明为抽象类**；要么**重写父类全部的抽象方法** |

```java
// 子类选择一：重写所有抽象方法
public class Dog extends Animal {
    @Override
    public void eat() {
        System.out.println("狗在啃骨头");
    }

    @Override
    public void sleep() {
        System.out.println("狗在睡觉");
    }
}

// 子类选择二：自己也是抽象类（把难题继续向下传递）
public abstract class Pet extends Animal {
    // 不重写，继续留给 Pet 的子类实现
}
```

---

### 11.3 抽象类的设计意义

```
抽象类的核心价值：强制子类必须实现某些行为
─────────────────────────────────────────
普通父类  → 子类可以选择性重写方法
抽象父类  → 子类必须重写全部抽象方法（否则也得是抽象类）
```
