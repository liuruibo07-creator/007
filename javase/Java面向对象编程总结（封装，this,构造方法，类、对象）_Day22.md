## 一、面向对象编程概述

**面向对象编程**（OOP，Object-Oriented Programming）是一种**编程思想**，用来指导我们写代码。

### 核心理念

> 当你想做某件事的时候，**找对象**来帮你完成。

### 优势

| 优势 | 说明 |
|------|------|
| **复用功能代码** | 功能封装在对象中，不需要自己重新实现 |
| **贴近生活思维** | 编程方式与现实生活中"找人/找工具做事"的思维方式高度一致 |

## 二、类与对象

### 2.1 类（Class）

**类**相当于一张**设计图纸**，描述一类事物的共同特征，是**抽象的**。

#### 类的组成

| 组成部分     | 说明          | 特点                          |
| -------- | ----------- | --------------------------- |
| **成员变量** | 描述对象的属性（状态） | 定义在**类中方法外**，不要显式初始化        |
| **成员方法** | 描述对象的行为     | 与普通方法相比，**去掉 `static` 关键字** |
| **构造方法** | 用于创建和初始化对象  | 详见第七节                       |

```java
public class Student {
    // 成员变量（不显式初始化）
    String name;
    int age;

    // 成员方法（无 static）
    public void study() {
        System.out.println(name + "正在学习");
    }
}
```

---

### 2.2 对象（Object）

**对象**是类的具体实例，是**客观存在的、具体的**一个事物。

```java
// 基于类创建对象
Student s = new Student();
```

---

### 2.3 类与对象的关系

```
类（设计图纸）──基于类创建──→ 对象1
                          ──→ 对象2
                          ──→ 对象3（一个类对应多个对象）
```

---

### 2.4 访问成员

```java
// 访问成员变量
对象名.成员变量

// 调用成员方法
对象名.成员方法(实参列表)

// 示例
Student s = new Student();
s.name = "张三";         // 访问成员变量
s.study();              // 调用成员方法
```

---

### 2.5 注意事项

> ⚠️ 一个 Java 源文件（`.java`）中可以定义**多个 class 类**，但**只能有一个类被 `public` 修饰**，且被 `public` 修饰的类名**必须与文件名完全一致**。

## 三、对象内存图

### 3.1 对象在内存中的存储

| 存储位置 | 存储内容 |
|----------|----------|
| **堆内存** | 对象本身（成员变量及其值） |
| **方法区** | 字节码文件（`.class` 文件） |
| **栈内存** | 对象变量（存储堆中对象的**地址值**） |

```
  栈内存                堆内存
┌─────────┐          ┌─────────────────────┐
│    s    │──地址──→ │ Student 对象         │
│ 0x1234  │          │ name = null          │
└─────────┘          │ age  = 0             │
                     │ 类地址 → 方法区       │
                     └─────────────────────┘
```

---

### 3.2 对象内存的四条核心规律

| 规律 | 说明 |
|------|------|
| **规律一** | 对象在**堆内存**中；成员变量来自字节码文件，有**默认值** |
| **规律二** | `new` 了几次，堆里就有**几个独立对象** |
| **规律三** | 字节码文件（`.class`）在**第一次使用时才加载**，且**只加载一次** |
| **规律四** | 两个变量指向同一个对象，**其中一方修改，另一方能看到修改后的结果** |

```java
// 规律四示例
Student s1 = new Student();
Student s2 = s1;          // s1 和 s2 指向同一个对象

s2.name = "李四";
System.out.println(s1.name);  // → "李四"（s1 也能看到修改）
```

## 四、自动垃圾回收

### 4.1 什么是垃圾

> 当一个对象**没有任何变量**来记录它的地址值时，该对象就变成了**垃圾**。

```java
Student s = new Student();  // 堆中创建对象
s = null;                   // s 不再指向该对象，对象变成垃圾
```

### 4.2 Java 的自动垃圾回收机制（GC）

| 特点 | 说明 |
|------|------|
| **自动触发** | Java 有专门的**垃圾回收器（GC）**，在 JVM 空闲时自动运行 |
| **无需手动** | 开发人员**不需要写代码**来手动释放内存 |
| **释放内存** | 自动回收无引用的对象，释放堆内存空间 |

> 💡 这是 Java 相比 C/C++ 的重要优势之一，大幅降低了内存泄漏的风险。

## 五、封装

### 5.1 什么是封装

**封装**是**面向对象编程三大特征之一**（另外两个是继承和多态），是一种**设计思想**，用来指导我们正确地设计对象的属性和行为。

### 5.2 设计规范

> **合理暴露，合理隐藏。**

### 5.3 代码层面实现

**第一步：用 `private` 修饰成员变量（隐藏）**

```java
public class Student {
    private String name;   // private 修饰后，只能在本类中使用
    private int age;
}
```

**第二步：提供 `public` 的 getter / setter 方法（暴露）**

```java
public class Student {
    private String name;
    private int age;

    // getter：获取值
    public String getName() {
        return name;
    }

    // setter：设置值（可在此处加入数据校验逻辑）
    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age > 0 && age < 150) {
            this.age = age;
        }
    }
}
```

### 5.4 封装的好处

| 好处 | 说明 |
|------|------|
| **保护数据** | 外部无法直接修改私有变量，防止非法赋值 |
| **控制访问** | 通过 setter 方法可以添加数据校验逻辑 |
| **隐藏实现细节** | 外部只需调用方法，无需关心内部实现 |

## 六、this 关键字

### 6.1 什么是 this

> **`this` 表示当前对象**：哪个对象调用了 `this` 所在的方法，`this` 就代表哪个对象。

### 6.2 应用场景

**解决成员变量与局部变量同名冲突：**

```java
public class Student {
    private String name;

    public void setName(String name) {
        // name = name;          // ❌ 错误：两个 name 都指局部变量（就近原则）
        this.name = name;        // ✅ 正确：this.name 是成员变量，name 是形参
    }
}
```

### 6.3 就近原则

> 在方法中，变量查找遵循**就近原则**：谁离得近，就代表谁。

```
局部变量（形参）距离当前代码最近 → 直接写 name 指局部变量
成员变量需要通过 this 区分 → this.name 指成员变量
```

### 6.4 this 的底层原理

> `this` 本质上是 JVM 在**成员方法中自动添加的第一个隐式形参**，指向调用该方法的对象。

## 七、构造方法

### 7.1 构造方法的定义规则

| 规则 | 说明 |
|------|------|
| 方法名与类名**完全相同** | 大小写也必须一致 |
| **没有返回值**，连 `void` 也不能写 | — |
| 支持**重载** | 可以定义多个构造方法，参数列表不同 |
| **建议**手动给出无参和全参构造 | 应对不同场景的对象创建需求 |

```java
public class Student {
    private String name;
    private int age;

    // 无参构造方法
    public Student() { }

    // 全参构造方法
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

---

### 7.2 构造方法的调用

> 构造方法**不需要手动调用**，系统在创建对象时**自动调用**。

```java
Student s1 = new Student();             // 自动调用无参构造
Student s2 = new Student("张三", 18);   // 自动调用全参构造
```

---

### 7.3 完整对象创建过程

```
① new → 在堆内存中开辟空间，并完成默认初始化
         （成员变量赋默认值：int→0，String→null，boolean→false）
         ↓
② 调用构造方法 → 完成显式初始化
         （将传入的参数值赋给成员变量）
```

---

### 7.4 两种完成显式初始化的方式

| 方式 | 代码示例 | 特点 |
|------|----------|------|
| **无参构造 + set 方法** | `Student s = new Student();` `s.setName("张三");` | 灵活，可选择性赋值 |
| **全参数构造方法** | `Student s = new Student("张三", 18);` | 简洁，一步完成初始化 |

---

### 7.5 构造方法注意事项

| 情况 | 结果 |
|------|------|
| **不写任何构造方法** | 系统自动添加一个**无参构造方法** |
| **手动写了构造方法** | 系统**不再**自动添加无参构造；若仍需要，必须**手动补写** |

```java
public class Student {
    String name;

    // 只写了全参构造
    public Student(String name) {
        this.name = name;
    }
    // ⚠️ 此时 new Student() 会报错，无参构造已不自动生成
    // ✅ 若需要，必须手动加上 public Student() {}
}
```
