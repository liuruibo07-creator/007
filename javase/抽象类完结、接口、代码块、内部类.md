## 一、抽象类回顾

### 作用

抽象类的核心定位是**抽象父类**。

> 当多个子类存在**共性方法**，向上抽取到父类时，若无法给出具体实现，则将该方法定义为**抽象方法**，父类因此变为**抽象父类**。

```java
public abstract class Animal {
    // 共性方法，但无法统一实现 → 抽象方法
    public abstract void eat();
    public abstract void sleep();
}
```

## 二、模板方法设计模式

### 2.1 解决什么问题

> 将做某件事的**顺序或步骤固定下来**，防止子类随意打乱流程，减少出错概率。

### 2.2 如何写

```
① 定义一个抽象类
② 在类中定义「模板方法」，描述固定的执行步骤
③ 模板方法中调用一系列「抽象方法」，由子类去具体实现
④ 模板方法建议用 final 修饰 → 防止子类重写，保证流程不被破坏
```

```java
public abstract class DataAnalyzer {

    // 模板方法：固定执行流程，final 修饰防止子类重写
    public final void analyze() {
        readData();    // ① 读取数据
        processData(); // ② 处理数据（各子类不同，抽象）
        outputData();  // ③ 输出结果
    }

    // 抽象方法：由子类实现各自的数据处理逻辑
    protected abstract void processData();

    private void readData()   { System.out.println("读取数据..."); }
    private void outputData() { System.out.println("输出结果..."); }
}

// 子类只需关注不同的步骤
public class SalesAnalyzer extends DataAnalyzer {
    @Override
    protected void processData() {
        System.out.println("处理销售数据...");
    }
}
```

## 三、接口的定义

### 3.1 基本语法

```java
public interface 接口名 {
    // 成员变量（默认：public static final）
    int MAX_SIZE = 100;  // 等同于 public static final int MAX_SIZE = 100;

    // 成员方法（默认：public abstract）
    void show();         // 等同于 public abstract void show();
}
```

### 3.2 接口成员的默认修饰符

| 成员类型 | 默认修饰符 | 说明 |
|----------|------------|------|
| **成员变量** | `public static final` | 接口中的变量本质上是**常量** |
| **成员方法** | `public abstract` | 接口中的方法默认为抽象方法 |
| **构造方法** | — | ❌ 接口**没有**构造方法 |

> ⚠️ 接口中**不能定义构造方法**，只能有成员变量和成员方法。

## 四、接口的使用

### 4.1 核心规则

| 规则 | 说明 |
|------|------|
| 接口不能创建对象 | `new 接口名()` ❌ 非法 |
| 通过 `implements` 实现接口 | `class 类名 implements 接口名 {}` |
| 一个类可以实现多个接口 | `class A implements B, C {}` |
| 可以同时继承父类并实现接口 | `class A extends B implements C, D {}` |
| 实现类的两种选择 | ① 重写所有抽象方法 ② 把自己声明为抽象类 |

```java
// 定义接口
public interface Flyable {
    void fly();
}

public interface Swimmable {
    void swim();
}

// 实现类：同时继承父类 + 实现多个接口
public class Duck extends Animal implements Flyable, Swimmable {

    @Override
    public void fly() {
        System.out.println("鸭子在飞");
    }

    @Override
    public void swim() {
        System.out.println("鸭子在游泳");
    }
}
```

## 五、接口的好处

| 好处 | 说明 |
|------|------|
| **① 指定规则** | 接口规定必须实现的行为，统一规范 |
| **② 接口多态** | 通用方法的形参类型声明为接口，可以接受**所有实现类的对象** |
| **③ 面向接口编程** | 程序依赖接口而非具体实现，降低耦合度，易于扩展维护 |

```java
// 接口多态示例：形参类型是接口，接受所有实现类对象
public static void letFly(Flyable f) {
    f.fly();
}

letFly(new Duck());   // ✅ 传入 Duck 对象
letFly(new Bird());   // ✅ 传入 Bird 对象
letFly(new Plane());  // ✅ 传入 Plane 对象
```

## 六、接口升级 — JDK 8 / 9 新特性

### 6.1 JDK 8 新增：默认方法 & 静态方法

#### 默认方法（`default`）

**定义：**

```java
public interface MyInterface {
    // default 关键字不能省略，权限 public 可省略
    public default void defaultMethod() {
        System.out.println("这是默认方法");
    }
}
```

**调用与重写：**

| 操作 | 方式 |
|------|------|
| **调用** | `实现类对象.默认方法()` |
| **重写** | 支持重写，重写时**去掉 `default` 关键字** |

```java
// 实现类重写默认方法（去掉 default）
public class MyClass implements MyInterface {
    @Override
    public void defaultMethod() {
        System.out.println("重写后的默认方法");
    }
}
```

---

#### 静态方法（`static`）

**定义：**

```java
public interface MyInterface {
    // static 关键字不能省略，权限 public 可省略
    public static void staticMethod() {
        System.out.println("这是静态方法");
    }
}
```

**调用与重写：**

| 操作 | 方式 |
|------|------|
| **调用** | `接口名.静态方法()` |
| **重写** | ❌ **不支持重写** |

---

#### 默认方法 vs 静态方法对比

| 对比项 | 默认方法（`default`） | 静态方法（`static`） |
|--------|----------------------|---------------------|
| 关键字 | `default`（不能省略） | `static`（不能省略） |
| 调用方式 | `对象.方法名()` | `接口名.方法名()` |
| 是否支持重写 | ✅ 支持 | ❌ 不支持 |

---

### 6.2 JDK 9 新增：私有方法

用于**抽取接口内部重复代码**，不对外暴露。

| 类型 | 语法 | 用途 |
|------|------|------|
| **普通私有方法** | `private 返回值类型 方法名(形参) { }` | 抽取**默认方法**中的重复代码 |
| **静态私有方法** | `private static 返回值类型 方法名(形参) { }` | 抽取**静态方法**中的重复代码 |

```java
public interface MyInterface {

    default void methodA() {
        commonCode();   // 调用私有方法
        System.out.println("A 的特有逻辑");
    }

    default void methodB() {
        commonCode();   // 调用私有方法
        System.out.println("B 的特有逻辑");
    }

    // 私有方法：抽取重复代码，仅供接口内部使用
    private void commonCode() {
        System.out.println("公共逻辑...");
    }
}
```

## 七、接口与接口的关系

> 接口与接口之间是**继承关系**，使用 `extends` 关键字。

| 特点 | 说明 |
|------|------|
| **支持单继承** | 一个接口可以继承另一个接口 |
| **支持多继承** | 一个接口可以同时继承多个接口 |

```java
public interface A { void methodA(); }
public interface B { void methodB(); }

// 接口多继承：C 同时拥有 A 和 B 的规范
public interface C extends A, B {
    void methodC();
}
```

## 八、接口使用注意事项

| 序号 | 情形 | 规则 |
|------|------|------|
| **① 多接口同名抽象方法** | 一个类实现了多个接口，多个接口中有同名抽象方法 | 实现类中**只需重写一个**即可 |
| **② 父类与接口同名方法** | 一个类继承父类同时实现接口，父类和接口中有同名方法 | **优先使用父类**中的方法 |
| **③ 多接口同名默认方法** | 一个类实现了多个接口，多个接口中有同名的**默认方法** | ❌ 编译报错，**必须强制重写**同名默认方法 |

```java
// 情形③：两个接口都有同名默认方法
public interface IA { default void show() { System.out.println("IA"); } }
public interface IB { default void show() { System.out.println("IB"); } }

// 必须手动重写，消除歧义
public class MyClass implements IA, IB {
    @Override
    public void show() {
        System.out.println("MyClass 重写，消除歧义");
    }
}
```
>

## 九、代码块

Java 中有三种代码块，定义位置和执行时机各不相同：

### 9.1 静态代码块

| 项目 | 说明 |
|------|------|
| **语法** | 定义在类中方法外，用 `static { }` 包裹 |
| **执行时机** | **类加载时执行，且只执行一次** |
| **作用** | 主要用来**初始化静态成员变量** |

```java
public class Config {
    static String url;

    // 静态代码块：类加载时自动执行，只执行一次
    static {
        url = "jdbc:mysql://localhost:3306/mydb";
        System.out.println("静态代码块执行了");
    }
}
```

---

### 9.2 构造代码块（实例代码块）

| 项目 | 说明 |
|------|------|
| **语法** | 定义在类中方法外，用 `{ }` 包裹（无 `static`） |
| **执行时机** | **每次创建对象时执行，优先于构造方法执行** |
| **作用** | 抽取多个**构造方法中的重复代码** |

```java
public class Student {
    String name;
    int age;

    // 构造代码块：每次 new 对象时都会先执行
    {
        System.out.println("构造代码块执行");
        // 公共初始化逻辑
    }

    public Student() { }
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

---

### 9.3 局部代码块

| 项目 | 说明 |
|------|------|
| **语法** | 定义在**方法体内**，用 `{ }` 包裹 |
| **作用** | 限制变量的作用域，**出了大括号内存立即释放** |

```java
public void method() {
    {
        int temp = 100;    // temp 只在这个代码块内有效
        System.out.println(temp);
    }
    // System.out.println(temp);  ❌ 超出作用域，编译报错
}
```

---

### 9.4 三种代码块对比

| 类型 | 位置 | 执行时机 | 执行次数 | 主要用途 |
|------|------|----------|----------|----------|
| **静态代码块** | 类中方法外 | 类加载时 | **一次** | 初始化静态成员变量 |
| **构造代码块** | 类中方法外 | 每次创建对象时（先于构造方法） | **每次** | 抽取构造方法重复代码 |
| **局部代码块** | 方法体中 | 随方法执行流程 | — | 提前释放局部变量内存 |

## 十、内部类

### 10.1 什么是内部类

> **定义在另一个类中的类**，称为内部类，外面的类称为外部类。

### 10.2 内部类的分类

```
内部类
├── 成员内部类（定义在类中方法外）
│   ├── 静态成员内部类（有 static 修饰）
│   └── 实例成员内部类（无 static 修饰）
├── 局部内部类（定义在方法中，了解即可）
└── 匿名内部类（重点）
```

---

### 10.3 静态成员内部类

| 项目 | 说明 |
|------|------|
| **创建对象** | `外部类名.内部类名 对象名 = new 外部类名.内部类名();` |
| **访问外部类成员** | 只能访问外部类的**静态成员** |

```java
public class Outer {
    static int num = 10;

    // 静态成员内部类
    public static class Inner {
        public void show() {
            System.out.println(num);   // ✅ 可以访问外部类静态成员
        }
    }
}

// 创建静态内部类对象
Outer.Inner inner = new Outer.Inner();
inner.show();
```

---

### 10.4 实例成员内部类

| 项目 | 说明 |
|------|------|
| **创建对象** | `外部类名.内部类名 对象名 = new 外部类名().new 内部类名();` |
| **访问外部类成员** | 可以访问外部类的**所有成员**（静态 + 实例） |

```java
public class Outer {
    int num = 10;

    // 实例成员内部类
    public class Inner {
        public void show() {
            System.out.println(num);   // ✅ 可以访问外部类实例成员
        }
    }
}

// 创建实例内部类对象（必须先创建外部类对象）
Outer.Inner inner = new Outer().new Inner();
inner.show();
```

### 10.5 匿名内部类 ⭐

#### 语法

```java
new 接口名或抽象父类名() {
    // 在此处重写方法
    @Override
    public void 方法名() {
        方法体
    }
};
```

#### 如何理解

> 匿名内部类将**类的定义、方法重写、创建对象**三步合并成一步完成。

```java
// 传统写法（三步）
class Dog extends Animal {          // ① 定义类
    @Override
    public void eat() {             // ② 重写方法
        System.out.println("狗吃骨头");
    }
}
Animal a = new Dog();               // ③ 创建对象

// 匿名内部类写法（一步搞定）
Animal a = new Animal() {
    @Override
    public void eat() {
        System.out.println("狗吃骨头");
    }
};
```

#### 本质

> 匿名内部类的本质是一个**对象**：
> - 实现了某接口的**实现类对象**，或
> - 继承了某抽象父类的**子类对象**

#### 应用场景

> **作为实参传递给通用方法** — 最常见的使用场景，省去单独定义实现类的麻烦。

```java
// 通用方法：形参是接口类型
public static void letEat(Animal a) {
    a.eat();
}

// 匿名内部类作为实参直接传入
letEat(new Animal() {
    @Override
    public void eat() {
        System.out.println("吃东西...");
    }
});
```

#### 匿名内部类 vs 普通实现类

| 对比项 | 普通实现类 | 匿名内部类 |
|--------|------------|------------|
| 是否需要起名 | ✅ 需要类名 | ❌ 不需要（匿名） |
| 是否可以复用 | ✅ 可以多次使用 | ❌ 只用一次 |
| 代码简洁度 | 较繁琐 | ✅ 简洁 |
| 适用场景 | 需要多次使用的实现 | **一次性使用**的实现 |
