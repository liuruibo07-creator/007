## 一、Linux 命令语法

Linux 命令的常见完整格式：

```text
命令名 [选项] [参数]
```

- 命令名：要执行的程序或内置命令。
- 选项：控制命令行为，通常可省略。
- 参数：命令操作的目标，数量取决于具体命令。
- 方括号表示该部分通常可选，实际输入时不写方括号。

### 1. 短选项

短选项由一个连字符和单个字母组成：

```bash
ls -a
ls -l
```

多个无参数的短选项通常可以合并：

```bash
ls -al
```

### 2. 长选项

长选项由两个连字符和完整单词组成：

```bash
ls --help
```

长选项通常不能像短选项一样合并。

### 3. 获取帮助

```bash
命令 --help
man 命令
```

示例：

```bash
ls --help
man tar
```

> 不同命令的选项含义可能不同，使用前应查看该命令的帮助文档。

## 二、终端与目录浏览

### 1. clear：清屏

```bash
clear
```

快捷键：

```text
Ctrl + L
```

它只清理当前终端显示，不会删除文件或命令历史。

### 2. ls：查看目录内容

```bash
ls [选项] [目录]
```

常见写法：

```bash
ls
ls -l
ls -a
ls -al /var/log
```

| 选项   | 作用                     |
| ---- | ---------------------- |
| `-a` | 显示所有内容，包括以 `.` 开头的隐藏文件 |
| `-l` | 显示权限、所有者、大小、时间等详细信息    |
| `-h` | 配合 `-l`，以易读单位显示大小      |

推荐组合：

```bash
ls -alh
```

部分发行版中：

```bash
ll
```

是 `ls -l` 或类似命令的 Shell 别名，并非所有系统都默认存在。

### 3. cd：切换目录

```bash
cd 目录路径
```

特殊路径：

| 表示 | 含义 |
|---|---|
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `~` | 当前用户的家目录 |
| `/` | 根目录 |
| `-` | 上一次所在目录 |

示例：

```bash
cd /usr/local
cd ..
cd ~
cd
cd -
```

执行不带参数的 `cd` 会回到当前用户家目录：

```text
root 用户：/root
普通用户：/home/用户名
```

### 4. pwd：显示当前位置

```bash
pwd
```

输出当前工作目录的绝对路径，执行文件操作前可用它确认位置。

## 三、查看文件内容

### 1. cat：查看全部内容

适合查看较短文件：

```bash
cat 文件名
cat -n 文件名
```

`-n` 表示显示行号。

> 对大文件直接使用 `cat` 会快速刷屏，优先使用 `less`。

### 2. more：分页查看

```bash
more 文件名
```

| 按键 | 作用 |
|---|---|
| `Enter` | 向下滚动一行 |
| `Space` | 向下滚动一页 |
| `b` | 返回上一页（实现支持时） |
| `q` | 退出 |

### 3. less：增强分页查看

```bash
less 文件名
```

| 按键 | 作用 |
|---|---|
| `Enter` / 方向键 | 移动一行 |
| `Space` | 下一页 |
| `b` | 上一页 |
| `/keyword` | 向下搜索 |
| `n` | 下一个匹配项 |
| `N` | 上一个匹配项 |
| `q` | 退出 |

`less` 不会把浏览过的全部文件内容永久铺满终端，功能通常比 `more` 完整。

### 4. head：查看文件开头

默认显示前 10 行：

```bash
head 文件名
```

指定行数：

```bash
head -n 20 文件名
head -20 文件名
```

### 5. tail：查看文件末尾

默认显示最后 10 行：

```bash
tail 文件名
```

指定行数：

```bash
tail -n 100 app.log
```

持续追踪追加内容：

```bash
tail -f app.log
```

先显示最后 100 行并持续跟踪：

```bash
tail -n 100 -f app.log
```

停止动态查看：

```text
Ctrl + C
```

## 四、创建和删除

### 1. mkdir：创建目录

```bash
mkdir 目录名
```

递归创建多级目录：

```bash
mkdir -p /opt/apps/demo/logs
```

`-p` 会按需创建不存在的父目录，目录已存在时通常不报错。

### 2. touch：创建文件或更新时间

```bash
touch app.log
```

- 文件不存在：创建空文件。
- 文件存在：更新其访问和修改时间，不会清空原内容。

### 3. rmdir：删除空目录

```bash
rmdir 目录名
```

只有目录为空时才能删除。

```bash
rmdir -p a/b/c
```

`-p` 会在删除子目录后，继续尝试删除变空的父目录。

### 4. rm：删除文件或目录

```bash
rm 文件名
rm -r 目录名
```

常见选项：

| 选项 | 作用 |
|---|---|
| `-r` | 递归删除目录及其内容 |
| `-f` | 强制执行，不询问且忽略不存在的目标 |
| `-i` | 删除前逐项确认 |

> [!WARNING]
> `rm -rf` 通常无法从回收站恢复。执行前先用 `pwd`、`ls -ld 目标` 核对绝对路径，避免对 `/`、家目录、工作区根目录或未展开的变量执行递归删除。

更安全的学习顺序：

```bash
pwd
ls -ld /明确/目标/路径
rm -ri /明确/目标/路径
```

确认目标无误后才考虑非交互方式。

## 五、复制、移动与重命名

### 1. cp：复制

复制文件到目录：

```bash
cp app.jar /opt/apps/
```

复制并重命名：

```bash
cp app.jar app-backup.jar
```

递归复制目录：

```bash
cp -r source-dir target-dir
```

保留大部分属性并递归复制，常用：

```bash
cp -a source-dir target-dir
```

目标目录存在时，源目录通常被复制到目标目录内部；目标不存在时，目标名称会成为新目录名。操作前应使用 `ls -ld` 确认目标是否存在。

### 2. mv：移动或重命名

移动文件：

```bash
mv app.jar /opt/apps/
```

重命名文件：

```bash
mv old-name.jar new-name.jar
```

移动目录：

```bash
mv source-dir target-dir
```

`cp` 会保留源文件；`mv` 成功后原路径不再保留源对象。

### 3. 操作前检查

为避免意外覆盖：

```bash
ls -ld source target
cp -i source target
mv -i source target
```

`-i` 会在覆盖已有文件前询问。

## 六、tar 归档与压缩

### 1. 归档与压缩的区别

- 归档：把多个文件和目录组合成一个文件，不一定减小体积。
- 压缩：通过算法减小数据体积。

`.tar` 是归档文件；`.tar.gz` 是 tar 归档后再用 gzip 压缩。

### 2. 常用选项

| 选项 | 作用 |
|---|---|
| `-c` | 创建归档 |
| `-x` | 解开归档 |
| `-t` | 列出归档内容，不解压 |
| `-v` | 显示处理过程 |
| `-f` | 指定归档文件名，后面紧跟文件名 |
| `-z` | 使用 gzip 压缩或解压 |
| `-C` | 切换到指定目录后操作 |

### 3. 创建 `.tar`

```bash
tar -cvf backup.tar file1 file2 directory/
```

### 4. 解开 `.tar`

```bash
tar -xvf backup.tar
```

### 5. 创建 `.tar.gz`

```bash
tar -zcvf backup.tar.gz directory/
```

现代 tar 也常能根据文件扩展名推断压缩格式：

```bash
tar -cvf backup.tar.gz directory/
```

但显式使用 `-z` 更容易表达意图。

### 6. 解压到指定目录

先创建并确认目标目录：

```bash
mkdir -p /opt/apps/demo
tar -zxvf backup.tar.gz -C /opt/apps/demo
```

### 7. 解压前查看内容

```bash
tar -tvf backup.tar
tar -ztvf backup.tar.gz
```

这有助于确认压缩包是否包含意外的绝对路径或目录层级。

## 七、Vim 编辑器

打开或创建文件：

```bash
vim 文件名
```

Vim 主要有三种模式：

```text
                    i / a / o
命令模式 ─────────────────────> 插入模式
   ↑                              │
   └──────────── Esc ─────────────┘

命令模式 ───── : ─────> 底行模式
   ↑                         │
   └──────── Esc ────────────┘
```

### 1. 命令模式

进入 Vim 后默认处于命令模式。

| 命令 | 作用 |
|---|---|
| `gg` | 跳到第一行 |
| `G` | 跳到最后一行 |
| `dd` | 删除/剪切当前行 |
| `5dd` | 删除当前行开始的 5 行 |
| `yy` | 复制当前行 |
| `5yy` | 复制当前行开始的 5 行 |
| `p` | 粘贴到当前行之后 |
| `P` | 粘贴到当前行之前 |
| `u` | 撤销 |
| `Ctrl + r` | 重做 |

### 2. 插入模式

| 命令 | 作用 |
|---|---|
| `i` | 在光标当前位置前插入 |
| `a` | 在光标当前位置后插入 |
| `o` | 在当前行下方新建一行并插入 |
| `I` | 在当前行行首插入 |
| `A` | 在当前行行尾插入 |

按 `Esc` 返回命令模式。

### 3. 底行模式

在命令模式按 `:` 进入：

| 命令 | 作用 |
|---|---|
| `:w` | 保存 |
| `:q` | 退出（没有未保存更改时） |
| `:wq` | 保存并退出 |
| `:q!` | 放弃修改并退出 |
| `:set number` | 显示行号 |

### 4. 搜索

```text
/keyword    向下搜索
n           下一个匹配项
N           上一个匹配项
```

## 八、Linux 软件安装方式

常见安装方式有四种：

| 方式 | 特点 | 适用场景 |
|---|---|---|
| 二进制包 | 解压后配置即可使用 | JDK、独立工具 |
| RPM | 安装单个系统软件包，依赖需自行处理 | 离线或指定 RPM |
| YUM/DNF | 从仓库下载并自动处理依赖 | 系统软件首选方式 |
| 源代码 | 编译后安装，可高度定制 | 特殊版本或编译选项 |

选择建议：

```text
系统仓库满足需要 → YUM/DNF
官方提供免安装包 → 二进制
只有离线 RPM → 按依赖顺序安装或本地仓库
需要定制编译 → 源码安装
```

## 九、YUM 软件源与软件安装

CentOS 7 课程环境可能需要替换为可用的软件源。软件源配置属于系统级操作，应先备份原配置，并使用与系统版本匹配、来源可信的仓库文件。

### 1. 刷新缓存

替换配置后常执行：

```bash
yum clean all
yum makecache
```

### 2. 安装 Vim

```bash
yum install -y vim
```

`-y` 表示自动同意安装提示。正式服务器上应先查看将要安装或升级的软件，避免盲目确认。

### 3. 查询软件

```bash
yum search vim
yum info vim
yum list installed | less
```

### 4. 仓库替换建议

安全流程：

1. 确认发行版和版本。
2. 备份 `/etc/yum.repos.d/` 中相关文件。
3. 使用可信镜像源提供的对应版本配置。
4. 清理并重建缓存。
5. 使用小型软件包验证仓库。

> 不要直接执行来源不明的仓库替换脚本或配置内容。

## 十、安装 JDK 17

导图采用二进制包安装方式。

### 1. 解压

假设安装包为 `jdk-17_linux-x64_bin.tar.gz`：

```bash
tar -zxvf jdk-17_linux-x64_bin.tar.gz -C /usr/local
```

查看实际目录名：

```bash
ls -ld /usr/local/jdk-17*
```

### 2. 配置环境变量

系统级配置可放在独立文件中，比直接修改 `/etc/profile` 更易维护：

```bash
vim /etc/profile.d/jdk17.sh
```

内容示例：

```bash
export JAVA_HOME=/usr/local/jdk-17.0.x
export PATH="$JAVA_HOME/bin:$PATH"
```

这里的路径应改成实际解压目录。

### 3. 使配置生效

```bash
source /etc/profile.d/jdk17.sh
```

### 4. 验证

```bash
java -version
javac -version
echo "$JAVA_HOME"
```

> 仅为单个应用提供 JDK 时，也可以直接在启动脚本中使用 JDK 的绝对路径，减少对全局环境的影响。

## 十一、安装与配置 MySQL

导图采用 RPM 方式安装 MySQL，并提到处理 MariaDB 冲突、开启远程访问和 3306 端口。

### 1. 安装前检查

```bash
cat /etc/centos-release
rpm -qa | grep -Ei 'mariadb|mysql'
```

系统中存在 MariaDB 软件包并不意味着一定要全部卸载。应先确认课程 MySQL RPM 是否冲突、机器是否已有数据，以及相关包是否被系统组件依赖。

> 删除数据库软件可能导致数据或依赖受损，必须先备份数据并核对精确包名。

### 2. RPM 安装思路

RPM 安装需要按依赖顺序安装服务器、客户端和公共组件。具体包名、顺序和初始化方式取决于 MySQL 版本，因此应以该版本官方安装说明为准。

安装后通常需要：

```bash
systemctl enable --now mysqld
systemctl status mysqld
```

然后查看初始化日志、设置管理员密码并执行安全初始化。

### 3. 创建远程业务账号

导图中的做法是把 `root` 的 `host` 改成 `%`：

```sql
update user set host='%' where user='root';
```

不建议这样做，因为它会扩大最高权限账号的远程攻击面。更安全的做法是创建权限受限的业务账号，并限制来源网段：

```sql
CREATE USER 'app_user'@'192.168.10.%'
IDENTIFIED BY '高强度密码';

GRANT SELECT, INSERT, UPDATE, DELETE
ON app_db.*
TO 'app_user'@'192.168.10.%';
```

完成后验证授权：

```sql
SHOW GRANTS FOR 'app_user'@'192.168.10.%';
```

### 4. 开放 3306 端口

导图提到：

```bash
systemctl stop firewalld
```

不建议为了数据库连接关闭整个防火墙。应只放行必要端口，并尽量限制来源地址。

使用防火墙区域永久开放端口的常见命令：

```bash
firewall-cmd --permanent --add-port=3306/tcp
firewall-cmd --reload
firewall-cmd --list-ports
```

在生产环境中，更推荐通过云安全组、内网、防火墙富规则或 VPN 限制只有应用服务器能访问数据库。

### 5. 检查监听和连接

```bash
ss -lntp | grep 3306
systemctl status mysqld
```

远程连接还需要同时确认：

- MySQL 监听地址。
- 数据库账号的 Host 范围。
- 用户权限。
- 主机防火墙。
- 云服务器安全组。
- 网络路由。

## 十二、重点速查表

| 需求 | 命令 |
|---|---|
| 查看当前位置 | `pwd` |

| 动态查看日志 | `tail -n 100 -f 文件` |
